# Migration: v21 or older to v22

Upgrade from **v21** (`parks_api/`, MySQL) to **v22** (`swiss-parks-sdk/`, SQLite).

**Coming from v20 or older?** Jump straight to v22 with this guide. You do not need to install v21 or any version in between first. See [coming from v20 or older](#coming-from-v20-or-older) for the extra template checks.

Offers are **not** copied from MySQL. v22 imports them again from the XML export. `migrate.php` only builds the SQLite file — it does **not** delete MySQL. Drop MySQL yourself in step 9, after the site works.

## Checklist (short)

1. Backup `parks_api/` (and optionally a MySQL dump)
2. Rename folder → `swiss-parks-sdk/`, fix `require_once`
3. Move your settings to `config/config.local.php` as an array (remove MySQL keys, add `db_path`)
4. Install v22 core files (ZIP or `upgrade-sdk.sh`)
5. Import the `SwissParks\Sdk` namespace and rename PHP methods to camelCase (`show_offers_filter` → `showOffersFilter`, …)
6. Update `MyView` / frontend assets / cron
7. Run migrate (unless `upgrade-sdk.sh` already did)
8. Test the site
9. Delete old v21 files and the MySQL database
10. Roll back only if step 8 failed

Details for each step below.

## Before you start

- PHP `8.2`–`8.5` with `pdo_sqlite`
- Working v21 install (`api_hash`, `park_id`, cron)
- Write access for `swiss-parks-sdk/writable/data/` and `writable/log/`
- Short downtime: no offers until migrate finishes

**Backup:** copy the whole `parks_api/` folder (especially `config.php`, `custom/`, custom templates). MySQL dump is optional archive only.

## Coming from v20 or older

The upgrade steps of v15–v21.1 do not need to be run, because v22 covers them:

- MySQL migrations: v22 drops MySQL and re-imports all offers from XML into a new SQLite file
- Core files: v22 replaces the whole core
- Frontend paths (`api-17`, `api-20`, `v21`): v22 loads `…/v22/` instead
- Config options added in v20–v21 (`hide_accessibility_filter`, `show_municipality_filter`): v22 falls back to defaults if they are missing

Only **custom templates** need changes on top of the steps below. The shipped templates already contain them.

| Added in | Template | Change |
| --- | --- | --- |
| v15 | `detail.tpl` | Optional: add `__OFFER_INTERNAL_INFOS__` to show internal infos of projects |
| v19 | `detail.tpl` | Add `__OFFER_ROUTE_LIST__` to show routes in the vicinity |
| v20 | `filter.tpl` | Add `__FILTER_ACCESSIBILITIES__` for the accessibility filter |
| v21 | `filter.tpl` | Add `__FILTER_MUNICIPALITIES__` for the municipality filter |
| v21 | `detail.tpl` | Remove `__OFFER_RESEARCH__` and `__OFFER_RESEARCH_DETAIL__`; otherwise they show up as raw text |

Compare your templates with `templates/standard/` from the v22 release.

## Step-by-step

### 1. Rename the SDK folder

```text
parks_api/  →  swiss-parks-sdk/
```

In your pages/CMS:

```php
require_once 'swiss-parks-sdk/autoload.php';
```

### 2. Fix config

Put your settings in `swiss-parks-sdk/config/config.local.php` (create the `config/` folder if needed). The file returns an array with only the keys you change; `config/config.php` holds the SDK defaults and is replaced on every update. A root-level `config.php` from v21 is ignored.

**Drop** the MySQL keys `db_hostname`, `db_port`, `db_username`, `db_password` and `db_database`; v22 does not read them.

**Add / keep:**

```php
<?php

return [
	'api_hash' => '...',                                  // unchanged
	'park_id' => 0,                                       // unchanged
	'db_path' => 'writable/data/park-offers.sqlite',
	'log_directory' => 'writable/log/',
	// If favorites are enabled:
	'favorites_script_path' => '/path/to/swiss-parks-sdk/public',
];
```

Convert every other v21 setting you changed from `$config['key'] = value;` to `'key' => value,`. Full options: [configuration](../configuration.md).

Composer instead of ZIP: install the package and use a project config outside `vendor/`, see [Composer installation](../new-installation.md#composer-installation).

### 3. Install v22 files

**Option A — script** (needs SSH; `config/config.local.php` with `db_path` already in place):

```bash
bash swiss-parks-sdk/bin/upgrade-sdk.sh 22.0
```

Downloads v22, updates core files, runs migrate. Then continue with steps 4–6 and 8–9 (skip step 7).

**Option B — ZIP:** replace the core files by hand as described in [upgrade without the script](../upgrading.md#zip-installation). Keep your `config/config.local.php`, `custom/` and own template folders.

### 4. Update your PHP code

All SDK classes are in the namespace `SwissParks\Sdk`. Add the import at the top of each file that uses them:

```php
use SwissParks\Sdk\SwissParksSdk;
```

Then search your project for old method names and rename, for example:

| v21 | v22 |
| --- | --- |
| `show_offers_filter` | `showOffersFilter` |
| `show_offers_list` | `showOffersList` |
| `show_offers_map` | `showOffersMap` |
| `show_offers_pagination` | `showOffersPagination` |
| `show_offer_detail` | `showOfferDetail` |
| `show_favorites` | `showFavorites` |
| `is_offer_detail` | `isOfferDetail` |
| `get_offers_list` | `getOffersList` |
| `toggle_favorite` | `toggleFavorite` |
| `set_script_url` | `setScriptUrl` |

More names: [SwissParksSdk methods](../../sdk-reference/swiss-parks-sdk.md).

The entry class is now `SwissParksSdk` (`$sdk = new SwissParksSdk($language)`); `ParksAPI` no longer exists. In custom views and helpers, use `$this->sdk` (not `$this->api`) for the SDK instance.

Old `helpers/*.php` calls → static methods on `Date`, `Format`, `Map`. Old global constants → class constants:

| v21 | v22 |
| --- | --- |
| `CATEGORY_EVENT`, `CATEGORY_PRODUCT`, … | `Category::EVENT`, `Category::PRODUCT`, … |
| `OFFER_STATUS_ACTIVE`, … | `OfferStatus::ACTIVE`, … |
| `GINTO_INFOS_AVAILABLE` | `SwissParksSdk::GINTO_INFOS_AVAILABLE` |
| `SDK_VERSION` | `SwissParksSdk::VERSION` |

### 5. Update `custom/MyView.php` (if you have one)

| v21 | v22 |
| --- | --- |
| `overwrite_template_data` | `overwriteTemplateData` |
| `list_offers` | `listOffers` |
| `get_favorites_link` | `getFavoritesLink` |
| `get_seo_detail_url` | `getSeoDetailUrl` |
| `$this->api` | `$this->sdk` |

`filter()`, `pagination()`, `detail()` stay the same. Your class now extends `SwissParks\Sdk\View` (add `use SwissParks\Sdk\View;`), and `class_view` takes the class name with namespace, for example `'class_view' => MyView::class`. See [templating and custom view](../templating-and-custom-view.md).

`ParksSwissView` and the `parks.swiss`, `nationalpark` and `pfyn` templates are no longer shipped. If you used them, copy them from [`examples/`](../../../examples/) in the repository into your project.

If a custom theme is still under `template/…`, move it to `templates/…` and set `template_folder`.

### 6. Frontend and cron

**Frontend:** remove jQuery / jQuery UI and the old `v21` asset tags from the SDK pages, then load the v22 bundle as described in [frontend assets](../quick-start-integration.md#frontend-assets). The map container id changes from `mapContainer` to `swiss-parks-map`.

**Cron:**

| v21 | v22 |
| --- | --- |
| `php scripts/cron.php` | `bash bin/sync.sh` |
| `php scripts/force_update.php` | `bash bin/sync.sh --force` |

### WordPress

Same steps as above, applied to your plugin or theme: camelCase methods in the shortcode, v22 assets in the enqueue code, and cron via `bin/sync.sh` instead of `scripts/cron.php`. Compare your plugin with the [WordPress integration](../wordpress-integration.md) sketch, especially the recommended configuration and the session start on `init`.

### 7. Run migrate

Skip if option A in step 3 already ran migrate successfully.

```bash
mkdir -p swiss-parks-sdk/writable/data swiss-parks-sdk/writable/log
# make those directories writable by the web server / CLI user
bash swiss-parks-sdk/bin/migrate.sh
```

This deletes any existing SQLite file, creates a new one from `database/schema.sql`, and imports all offers from XML.

### 8. Test

Before deleting MySQL or old folders:

- [ ] File `writable/data/park-offers.sqlite` exists and has offers
- [ ] Filter, list, detail work
- [ ] Map works (if used)
- [ ] Favorites work (if used)
- [ ] No JS errors; cron: `bash swiss-parks-sdk/bin/sync.sh`
- [ ] Logs in `writable/log/` look clean

### 9. Cleanup (only after step 8 is OK)

**Old files** under `swiss-parks-sdk/` — delete if still present:

- `helpers/`, `language/`, `template/` (singular), `scripts/`
- Root `config.php`, old root `log/` (if you use `writable/log/`)

**MySQL** — v22 does not use it:

1. Confirm no `db_hostname` / `db_username` / `db_password` / `db_database` keys remain in `config/config.local.php`
2. Drop the old SDK database (your former `db_database` name), e.g. in phpMyAdmin or:

```sql
DROP DATABASE `your_old_sdk_database`;
```

3. Remove the MySQL user if it existed only for this SDK
4. Leave the MySQL **server** installed if other sites still need it

**Cron:** remove any leftover `scripts/cron.php` / HTTP cron URLs.

### 10. Rollback (if step 8 failed)

1. Restore the `parks_api/` backup
2. Put MySQL credentials back into v21 `config.php`
3. Restore old frontend URLs and cron
4. Confirm v21 import works again

You can delete the v22 SQLite file; v21 does not use it.

## What changed (reference)

| | v21 | v22 |
| --- | --- | --- |
| Folder | `parks_api/` | `swiss-parks-sdk/` |
| Database | MySQL/MariaDB | SQLite file (`db_path`) |
| Config | `parks_api/config.php` | `config/config.local.php` (array) |
| Classes | global (`ParksAPI`, `ParksView`, …) | namespace `SwissParks\Sdk` (`SwissParksSdk`, `View`, …) |
| Cron | `scripts/cron.php` | `bin/sync.sh` |
| Favorites | `scripts/favorite.php` | `public/favorites.php` |
| PHP API | `snake_case` | `camelCase` |
| Frontend | `…/v21/` + jQuery | `…/v22/` as `type="module"` |
| Map id | `mapContainer` | `swiss-parks-map` |
