# Migration: v21 to v22

Upgrade from **v21** (`parks_api/`, MySQL) to **v22** (`swiss-parks-sdk/`, SQLite).

Offers are **not** copied from MySQL. v22 imports them again from the XML export. `migrate.php` only builds the SQLite file — it does **not** delete MySQL. Drop MySQL yourself in step 9, after the site works.

## Checklist (short)

1. Backup `parks_api/` (and optionally a MySQL dump)
2. Rename folder → `swiss-parks-sdk/`, fix `require_once`
3. Move config to `config/config.php` (remove MySQL keys, add `db_path`)
4. Install v22 core files (ZIP or `upgrade-sdk.sh`)
5. Rename PHP methods to camelCase (`show_offers_filter` → `showOffersFilter`, …)
6. Update `MyView` / frontend assets / cron
7. Run migrate (unless `upgrade-sdk.sh` already did)
8. Test the site
9. Delete old v21 files and the MySQL database
10. Roll back only if step 8 failed

Details for each step below.

## Before you start

- PHP `8.2`–`8.5` with `pdo_sqlite`
- Working v21 install (`api_hash`, `park_id`, cron)
- Write access for `swiss-parks-sdk/writable/data/` and `writable/log/`
- Short downtime: no offers until migrate finishes

**Backup:** copy the whole `parks_api/` folder (especially `config.php`, `custom/`, custom templates). MySQL dump is optional archive only.

## Step-by-step

### 1. Rename the SDK folder

```text
parks_api/  →  swiss-parks-sdk/
```

In your pages/CMS:

```php
require_once 'swiss-parks-sdk/autoload.php';
```

### 2. Fix config

Put settings in `swiss-parks-sdk/config/config.php` (create the `config/` folder if needed). A root-level `config.php` from v21 is ignored.

**Remove:**

```php
$config['db_hostname'] = '...';
$config['db_port'] = 3306; // if set
$config['db_username'] = '...';
$config['db_password'] = '...';
$config['db_database'] = '...';
```

**Add / keep:**

```php
$config['api_hash'] = '...';           // unchanged
$config['park_id'] = ...;              // unchanged
$config['db_path'] = 'writable/data/park-offers.sqlite';
$config['log_directory'] = 'writable/log/';
```

If favorites are enabled:

```php
$config['favorites_script_path'] = '/path/to/swiss-parks-sdk/public';
```

Full options: [configuration](../configuration.md).

### 3. Install v22 files

**Option A — script** (needs SSH; `config/config.php` with `db_path` already in place):

```bash
bash swiss-parks-sdk/bin/upgrade-sdk.sh 22
```

Downloads v22, updates core files, runs migrate. Then continue with steps 4–6 and 8–9 (skip step 7).

**Option B — ZIP:** Download `swiss-parks-php-sdk-22.zip` from [GitHub Releases](https://github.com/indual-web/swiss-parks-php-sdk/releases). Copy into `swiss-parks-sdk/`:

- Replace: `autoload.php`, `classes/`, `database/`, `lang/`, `bin/`, `public/`, shipped `templates/`, `config/config.dist.php`
- Keep: your `config/config.php`, `custom/`, your own template folders

Do **not** overwrite `config/config.php`.

### 4. Update your PHP to camelCase

Search your project for old method names and rename, for example:

| v21 | v22 |
| --- | --- |
| `show_offers_filter` | `showOffersFilter` |
| `show_offers_list` | `showOffersList` |
| `show_offers_map` | `showOffersMap` |
| `show_offers_pagination` | `showOffersPagination` |
| `show_offer_detail` | `showOfferDetail` |
| `show_favorites` | `showFavorites` |
| `is_offer_detail` | `isOfferDetail` |
| `get_offers_list` | `getOffersList` |
| `toggle_favorite` | `toggleFavorite` |
| `set_script_url` | `setScriptUrl` |

More names: [ParksSDK methods](../../sdk-reference/parks-sdk.md).

The entry class is now `ParksSDK` (`$sdk = new ParksSDK($language)`). `ParksAPI` remains as a `class_alias` for existing code. In custom views and helpers, use `$this->sdk` (not `$this->api`) for the SDK instance.

Old `helpers/*.php` calls → static methods on `ParksDate`, `ParksFormat`, `ParksMap`.

### 5. Update `custom/MyView.php` (if you have one)

| v21 | v22 |
| --- | --- |
| `overwrite_template_data` | `overwriteTemplateData` |
| `list_offers` | `listOffers` |
| `get_favorites_link` | `getFavoritesLink` |
| `get_seo_detail_url` | `getSeoDetailUrl` |
| `$this->api` | `$this->sdk` |

`filter()`, `pagination()`, `detail()` stay the same. See [templating and custom view](../templating-and-custom-view.md).

`ParksSwissView` now lives in `classes/` (not `custom/`). Keep `class_view = 'ParksSwissView'` if you used it.

If a custom theme is still under `template/…`, move it to `templates/…` and set `template_folder`.

### 6. Frontend and cron

**Frontend:** remove jQuery / jQuery UI from the SDK pages. Load v22 (see `index.php` in the release):

```html
<link href="https://staging-map.angebote.paerke.ch/dist/frontend/v22/css/parks.min.css" rel="stylesheet">
<script type="module" src="https://staging-map.angebote.paerke.ch/dist/frontend/v22/parks.min.js"></script>
```

Map container id must be `swiss-parks-map` (not `mapContainer`). Switch to the production CDN host before go-live when it is published.

**Cron:**

| v21 | v22 |
| --- | --- |
| `php scripts/cron.php` | `bash bin/sync.sh` |
| `php scripts/force_update.php` | `bash bin/sync.sh --force` |

### WordPress

Same steps as above. Extra checks for a plugin/theme embed:

- Config: `return_output = true`, `soft_errors = true`
- Prefer `seo_urls = false` unless you add rewrite rules
- `db_path` / `log_directory`: absolute writable paths (for example under uploads)
- Always enqueue `parks.min.css` / `parks.min.js` yourself (`type="module"`); remove old jQuery tags
- Start the PHP session on WordPress `init` when `use_sessions` is true (shortcode is too late)
- Shortcode/plugin: camelCase methods; pass the offers permalink into `ParksSDK` as `$page_url`
- Do not call `setScriptUrl()` with only the page path if `seo_urls` is true (breaks detail detection)
- Cron via system cron or WP-CLI (`bin/sync.sh`), not HTTP to old `scripts/cron.php`

Details and sketch: [WordPress integration](../wordpress-integration.md).

### 7. Run migrate

Skip if option A in step 3 already ran migrate successfully.

```bash
mkdir -p swiss-parks-sdk/writable/data swiss-parks-sdk/writable/log
# make those directories writable by the web server / CLI user
bash swiss-parks-sdk/bin/migrate.sh
```

This deletes any existing SQLite file, creates a new one from `database/schema.sql`, and imports all offers from XML.

### 8. Test

Before deleting MySQL or old folders:

- [ ] File `writable/data/park-offers.sqlite` exists and has offers
- [ ] Filter, list, detail work
- [ ] Map works (if used)
- [ ] Favorites work (if used)
- [ ] No JS errors; cron: `bash swiss-parks-sdk/bin/sync.sh`
- [ ] Logs in `writable/log/` look clean

### 9. Cleanup (only after step 8 is OK)

**Old files** under `swiss-parks-sdk/` — delete if still present:

- `helpers/`, `language/`, `template/` (singular), `scripts/`
- Root `config.php`, old root `log/` (if you use `writable/log/`)

**MySQL** — v22 does not use it:

1. Confirm no `db_hostname` / `db_username` / `db_password` / `db_database` keys remain in `config/config.php`
2. Drop the old SDK database (your former `db_database` name), e.g. in phpMyAdmin or:

```sql
DROP DATABASE `your_old_sdk_database`;
```

3. Remove the MySQL user if it existed only for this SDK
4. Leave the MySQL **server** installed if other sites still need it

**Cron:** remove any leftover `scripts/cron.php` / HTTP cron URLs.

### 10. Rollback (if step 8 failed)

1. Restore the `parks_api/` backup
2. Put MySQL credentials back into v21 `config.php`
3. Restore old frontend URLs and cron
4. Confirm v21 import works again

You can delete the v22 SQLite file; v21 does not use it.

## What changed (reference)

| | v21 | v22 |
| --- | --- | --- |
| Folder | `parks_api/` | `swiss-parks-sdk/` |
| Database | MySQL/MariaDB | SQLite file (`db_path`) |
| Config | `parks_api/config.php` | `config/config.php` |
| Cron | `scripts/cron.php` | `bin/sync.sh` |
| Favorites | `scripts/favorite.php` | `public/favorites.php` |
| PHP API | `snake_case` | `camelCase` |
| Frontend | `…/v21/` + jQuery | `…/v22/` as `type="module"` |
| Map id | `mapContainer` | `swiss-parks-map` |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| SSL / cURL import errors | `$config['curl_verify_ssl'] = false;` (hosting fallback only) |
| Cannot write SQLite file | Fix permissions on `writable/data/` |
| Empty offer list | Check `api_hash` / `park_id`, logs; then `bash bin/sync.sh --force` |
| `show_offers_*` undefined | Still snake_case — finish steps 4–5 |
| Map tab empty | v22 JS as `type="module"`, container `swiss-parks-map` |
| Favorites 404 | Set `favorites_script_path` to the `public/` folder (or CMS wrapper) |
