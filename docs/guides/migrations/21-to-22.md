# Migration: v21 to v22

This guide covers the upgrade from **SDK version 21** (MySQL/MariaDB, folder `parks_api/`) to **version 22** (SQLite, folder `swiss-parks-sdk/`).

v22 is the first public release with a file-based SQLite database. There is no MySQL-based v22. Use this guide end to end; the generic [upgrade guide](../upgrading.md) alone is not enough for v21.

## Overview

| Area | v21 | v22 |
| --- | --- | --- |
| SDK folder | `parks_api/` | `swiss-parks-sdk/` |
| PHP | `>= 7.4` and `<= 8.4` | `>= 8.2` and `<= 8.5` with `pdo_sqlite` |
| Database | MySQL/MariaDB server | SQLite file (`db_path`) |
| Schema setup | Import `database/database.sql` | `database/schema.sql` (automatic via `migrate.php`) |
| Config file | `parks_api/config.php` | `swiss-parks-sdk/config/config.php` |
| Config keys | `db_hostname`, `db_username`, `db_password`, `db_database` (optional `db_port`) | `db_path`, optional `curl_verify_ssl`, `migration_log_url` |
| Logs | `log/` | `writable/log/` (`log_directory`) |
| Language files | `language/` | `lang/` |
| Templates | `template/` | `templates/` |
| CLI / cron | `scripts/cron.php`, `scripts/force_update.php` | `bin/sync.sh`, `bin/sync.sh --force` |
| Favorites endpoint | `scripts/favorite.php` | `public/favorites.php` |
| Helpers | `helpers/*.php` functions | `ParksDate`, `ParksFormat`, `ParksMap` classes |
| PHP API | `snake_case` (`show_offers_filter`, …) | `camelCase` (`showOffersFilter`, …) |
| Frontend assets | `…/assets/dist/v21/` (+ jQuery / jQuery UI) | `…/dist/frontend/v22/` (`type="module"`, no jQuery) |
| Map container id | `mapContainer` | `swiss-parks-map` |
| Data source | XML export (unchanged) | XML export (unchanged) |

No offer data is migrated from MySQL. The SQLite database is rebuilt from the XML export — same model as before, different storage.

v22 also stores custom map layer service URLs per language (`map_layer_i18n.url`) and reads optional XML `<ServiceURL language="…">` nodes. Legacy `<URL language="de,fr,…">` remains supported for older SDKs. Popup titles are language-specific too (`map_layer_i18n.popup_title` from `<Title language="…">`) and are emitted as `titleTemplate` on the map (`titleField` remains as fallback).

## Before you start

**Prerequisites**

- Running SDK version 21 with a working cron/import
- Valid `api_hash` and `park_id` in your config
- PHP `8.2`–`8.5` with `pdo_sqlite`
- Write permissions for the web server on `swiss-parks-sdk/writable/data/` and `swiss-parks-sdk/writable/log/` (created automatically when writable)

**Backup**

1. Full backup of your `parks_api/` folder (especially `config.php`, `custom/`, custom templates under `template/`).
2. Optional: MySQL dump for archival purposes only — v22 does not read it.

**Downtime**

Plan a short maintenance window. Pages may show no offers until `migrate.php` completes successfully.

## Step-by-step migration

### 1. Move and update config

Create `swiss-parks-sdk/config/` (after the folder rename in step 2, or prepare the file content now) and place your settings in `config/config.php`.

Keep `api_hash`, `park_id`, and your other custom settings. Remove MySQL keys and switch paths to the v22 layout.

**Remove (v21):**

```php
$config['db_hostname'] = '...';
$config['db_port'] = 3306; // if set
$config['db_username'] = '...';
$config['db_password'] = '...';
$config['db_database'] = '...';
```

**Add or change (v22):**

```php
$config['db_path'] = 'writable/data/park-offers.sqlite';
$config['log_directory'] = 'writable/log/';
$config['curl_verify_ssl'] = true; // default; see troubleshooting
```

If favorites are enabled, point the script path at the new public endpoint (folder or full URL to `favorites.php`):

```php
$config['favorites_script_path'] = '/path/to/swiss-parks-sdk/public';
```

`autoload.php` loads `config/config.php` (and optional `config.local.php`). A root-level `config.php` from v21 is no longer read.

See [configuration.md](../configuration.md) for all v22 options.

### 2. Rename SDK folder and update `require_once`

Rename your existing `parks_api/` directory to `swiss-parks-sdk/` and update integration PHP files:

```php
require_once('swiss-parks-sdk/autoload.php');
```

Ensure the edited config from step 1 lives at `swiss-parks-sdk/config/config.php` (move it out of the SDK root if it is still there).

### 3. Replace core files

**CLI alternative** (after steps 1 and 2 — `config/config.php` must already contain `db_path`):

```bash
bash swiss-parks-sdk/bin/upgrade-sdk.sh 22
```

This downloads the v22 release, updates core files, and runs `migrate.php`. Skip the manual file copy and step 7 below if you use the script. You still must complete steps 4–6 (PHP API, custom view, frontend, cron) yourself.

**Manual:** From the version 22 release ZIP (`swiss-parks-php-sdk-22.zip`), copy into `swiss-parks-sdk/`:

- `autoload.php`
- `classes/`
- `database/`
- `lang/`
- `bin/`
- `public/`
- `templates/` (shipped themes; keep your own custom template folders)
- `config/config.dist.php` (reference only; do not overwrite your `config/config.php`)

**Keep unchanged:**

- `config/config.php` (your edited file from step 1)
- `custom/` (your `MyView.php` and other overrides — update method names in step 5)
- Custom template folders under `templates/` (formerly `template/`)
- Existing log files if you move them into `writable/log/`

Do not keep v21 `helpers/`, `language/`, `template/` (singular), or `scripts/` as the runtime layout. `upgrade-sdk.sh` removes leftover `helpers/`, `language/`, and `template/` after updating.

`ParksSwissView` ships in `classes/` in v22 (no longer under `custom/`). Keep `class_view = 'ParksSwissView'` if you used that theme; otherwise keep your own `MyView`.

### 4. Update integrator PHP to camelCase

Public `ParksAPI` methods are camelCase in v22. Update every call site in your pages/CMS embeds, for example:

| v21 | v22 |
| --- | --- |
| `show_offers_filter` | `showOffersFilter` |
| `show_offers_list` | `showOffersList` |
| `show_offers_map` | `showOffersMap` |
| `show_offers_pagination` | `showOffersPagination` |
| `show_offer_detail` | `showOfferDetail` |
| `show_favorites` | `showFavorites` |
| `show_total` | `showTotal` |
| `show_offer_poi_list` | `showOfferPoiList` |
| `is_offer_detail` | `isOfferDetail` |
| `is_filter_activated` | `isFilterActivated` |
| `get_filter_data` | `getFilterData` |
| `get_offers_list` | `getOffersList` |
| `get_offer_detail` | `getOfferDetail` |
| `get_categories_list` | `getCategoriesList` |
| `get_categories_list_for_select` | `getCategoriesListForSelect` |
| `toggle_favorite` | `toggleFavorite` |
| `clean_favorites` | `cleanFavorites` |
| `set_script_url` | `setScriptUrl` |

Full reference: [parks-api.md](../../sdk-reference/parks-api.md).

If your custom code called helper functions from `helpers/date_helper.php`, `format_helper.php`, or `map_helper.php`, switch to the static methods on `ParksDate`, `ParksFormat`, and `ParksMap`.

### 5. Update `custom/MyView.php` (and other overrides)

Rename overridden methods to match `ParksView` in v22, for example:

| v21 | v22 |
| --- | --- |
| `overwrite_template_data` | `overwriteTemplateData` |
| `list_offers` | `listOffers` |
| `get_favorites_link` | `getFavoritesLink` |
| `get_seo_detail_url` | `getSeoDetailUrl` |

`filter()`, `pagination()`, and `detail()` keep the same names. Map markup for the overview is produced via `ParksAPI::showOffersMap()` / `getOverviewMap()` — do not rely on a public `ParksView::map()` override from v21.

See [templating and custom view](../templating-and-custom-view.md).

### 6. Update frontend assets and cron

**Frontend (required on overview and detail pages):**

- Remove v21 jQuery / jQuery UI script tags.
- Load the v22 bundle (see `index.php` in the release). Staging example until production CDN is published:

```html
<link href="https://staging-map.angebote.paerke.ch/dist/frontend/v22/css/parks.min.css" rel="stylesheet">
<script type="module" src="https://staging-map.angebote.paerke.ch/dist/frontend/v22/parks.min.js"></script>
```

- Ensure the map container id is `swiss-parks-map` (not `mapContainer`). Older JS builds leave the map tab empty.

**Cron:**

| v21 | v22 |
| --- | --- |
| `php scripts/cron.php` | `bash bin/sync.sh` |
| `php scripts/force_update.php` | `bash bin/sync.sh --force` |

Update crontab entries accordingly. Prefer CLI over hitting PHP scripts via HTTP.

### 7. Ensure writable directories and run migration

```bash
mkdir -p swiss-parks-sdk/writable/data swiss-parks-sdk/writable/log
chmod 775 swiss-parks-sdk/writable/data swiss-parks-sdk/writable/log   # adjust for your host
```

The web server user must be able to create and write `swiss-parks-sdk/writable/data/park-offers.sqlite`.

```bash
php /{PATH-TO-YOUR-SDK-FOLDER}/bin/migrate.php
# or:
bash swiss-parks-sdk/bin/migrate.sh
```

This command:

1. Deletes the existing SQLite file (if any)
2. Creates a new database from `database/schema.sql`
3. Runs a full import from the XML export

Use CLI when possible. On production, prefer `bash swiss-parks-sdk/bin/migrate.sh`.

Skip this step only if `upgrade-sdk.sh` already ran migrate successfully in step 3.

### 8. Validate

Check on your site:

- [ ] Filter loads and returns results
- [ ] Offer list displays correctly
- [ ] Map markers appear (if map is used; container `swiss-parks-map`)
- [ ] Offer detail page works
- [ ] Multilingual URLs (if SEO URLs enabled)
- [ ] Favorites toggle and overview (if used; endpoint `public/favorites.php`)
- [ ] Browser console: no JS errors / missing module
- [ ] Logs in `writable/log/`: no import errors
- [ ] Custom `MyView` / templates still render as expected

Verify cron still works:

```bash
bash swiss-parks-sdk/bin/sync.sh
```

### 9. Cleanup (after successful validation)

- MySQL database and credentials on the server can be decommissioned
- Remove old MySQL config keys from `config/config.php` if any remain
- Remove leftover v21 paths (`helpers/`, `language/`, `template/`, `scripts/`, root `config.php`, `log/` if migrated)
- Old MySQL dumps in project folders are no longer needed for runtime

### 10. Rollback

If validation fails:

1. Restore the v21 file backup (`parks_api/`)
2. Ensure MySQL credentials are back in `config.php`
3. Restore previous frontend asset URLs and cron commands
4. Confirm v21 cron/import still works against the MySQL database

The v22 SQLite file can be deleted; it is not used by v21.

## Troubleshooting

### HTTPS / cURL errors during import

Some shared hosting environments cannot validate SSL certificates. Symptom: import fails with cURL or SSL errors.

**Fix:** Set in `config/config.php`:

```php
$config['curl_verify_ssl'] = false;
```

Use only as a fallback. See [configuration.md](../configuration.md).

### Permission denied on database file

Symptom: errors creating or writing `writable/data/park-offers.sqlite`.

**Fix:** Ensure `swiss-parks-sdk/writable/data/` exists and is writable by the PHP/web server user.

### Empty offer list after migration

**Check:**

1. `api_hash` and `park_id` unchanged and correct
2. Migration finished without errors (check `writable/log/`)
3. Re-run: `bash swiss-parks-sdk/bin/sync.sh --force`

### Fatal error: call to undefined method (`show_offers_*` / `overwrite_template_data`)

Your integration or `MyView` still uses v21 `snake_case`. Rename to camelCase (steps 4–5).

### Map tab stays empty

**Check:**

1. `parks.min.js` is the v22 build and loaded with `type="module"`
2. Container id is `swiss-parks-map`
3. Overview markup still matches the tab structure expected by `parks.min.js` (see `index.php`)

### «SDK version out of date» in logs

Run `migrate.php` again after replacing `autoload.php` and `classes/`.

### Favorites links 404

Update `favorites_script_path` to the folder that contains `public/favorites.php`, or to your CMS wrapper URL. Legacy `scripts/favorite.php` is gone.

## What stays the same

- XML export as single source of truth
- Integration via `new ParksAPI($language)` in your pages
- Favorites and SEO URL *concepts* (paths and method names change as above)
- Sync idea: incremental update vs forced full import (`bin/sync.sh` / `--force`)
